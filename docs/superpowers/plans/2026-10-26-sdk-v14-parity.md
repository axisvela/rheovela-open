# Open SDK v1.4.0 Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring Python, TypeScript, Java, and Rust worker SDKs to the Go SDK’s v1.4.0 work-item surface.

**Architecture:** Add the full work-item HTTP client surface and a rich `WorkResult` callback to each SDK. Python/TS use native objects; Java/Rust stay dependency-free and carry arbitrary JSON as raw text. Each language gets its own tests and CI job.

**Tech Stack:** Python stdlib, TypeScript/Node 22, Java 21 stdlib, Rust std-only.

**Spec:** `docs/superpowers/specs/2026-10-26-sdk-v14-parity-design.md`

### Task 1: Python SDK v1.4.0

**Files:** `sdk/python/worker.py`, `sdk/python/test_worker.py`, `sdk/python/README.md`, `sdk/python/README.en.md`

- [ ] Add dataclasses:
  ```python
  @dataclass
  class Approval:
      state: str
      pending_stage: str | None = None
      final_args: Any = None
      reason: str | None = None
      requested_by: str | None = None
      requested_at: str | None = None
      decided_by: str | None = None
      decided_at: str | None = None
      comment: str | None = None
      checkpoint_ref: str | None = None
      effect_cursor: str | None = None

  @dataclass
  class WorkItem:
      id: str
      instance_id: str = ""
      activity_id: str = ""
      state: str = ""
      result: Any = None
      checkpoint_ref: str = ""
      effect_cursor: str = ""
      attempts: int = 0
      max_attempts: int = 0
      last_error: str = ""
      approval: Approval | None = None

  @dataclass
  class ApprovalRequest:
      actor: str = ""
      reason: str = ""
      final_args: Any = None
      checkpoint_ref: str = ""
      effect_cursor: str = ""

  @dataclass
  class WorkResult:
      status: str
      error: str = ""
      outcome: str = ""
      result: Any = None
      checkpoint_ref: str = ""
      effect_cursor: str = ""
      approval: ApprovalRequest | None = None

      @staticmethod
      def success(result=None, checkpoint_ref="", effect_cursor=""): ...
      @staticmethod
      def failure(error): ...
      @staticmethod
      def request_approval(approval): ...
  ```
- `Client.get_work_item(id)` -> GET `/api/v1/work-items/{id}`.
- `Client.poll(instance_id=None)` returns `list[WorkItem]`, parsing all fields.
- `Client.complete(id, token, result=None, checkpoint_ref="", effect_cursor="")`: body includes only non-empty optional fields.
- `Client.request_approval(id, token, req)`, `approve(id, actor, comment="", final_args=None)`, `reject(id, actor, reason)`, `cancel(id)`.
- Worker callback returns `WorkResult`; on `approval` call request_approval; on missing approval request fail.
- Tests: result complete body, approval request, approve/reject/cancel paths, get work item fields, global poll, worker success/failure/approval.
- Run `python -m py_compile sdk/python/worker.py` and `python -m unittest discover -s sdk/python`.
- Commit `feat(sdk-python): align worker with v1.4.0`.

### Task 3: Java SDK v1.4.0

**Files:** `sdk/java/worker/Worker.java`, `sdk/java/example/Example.java`, `sdk/java/README.md`, `sdk/java/README.en.md`

- [ ] Extend `WorkItem` record with result/checkpoint/effect/attempts/max/lastError/approval.
- Add records:
  ```java
  public record Approval(String state, String pendingStage, String finalArgs, String reason,
      String requestedBy, String requestedAt, String decidedBy, String decidedAt,
      String comment, String checkpointRef, String effectCursor) {}

  public record ApprovalRequest(String actor, String reason, String finalArgs,
      String checkpointRef, String effectCursor) {}

  public record Result(String status, String error, String outcome, String result,
      String checkpointRef, String effectCursor, ApprovalRequest approval) {
      public static Result ok() { ... }
      public static Result success(String result, String checkpointRef, String effectCursor) { ... }
      public static Result fail(String error) { ... }
      public static Result approval(ApprovalRequest req) { ... }
  }
  ```
- Raw JSON strings are embedded as-is for `result` and `finalArgs`.
- Client methods: `get`, `complete(id, token)`, `complete(id, token, result, checkpoint, effect)`, `requestApproval`, `approve`, `reject`, `cancel`.
- Extend JSON helpers to extract a raw JSON value for `result`/`final_args` if needed.
- Worker callback `BiFunction<WorkItem,String,Result>`; handle approval.
- Update `Example` fake server to exercise result complete, approval, approve/reject/cancel and throw on mismatch so CI fails.
- Run `javac` + `java example.Example`.
